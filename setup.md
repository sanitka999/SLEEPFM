# SleepFM Local Setup and Demo Runbook

This runbook keeps the upstream SleepFM model code unchanged and adds a
reproducible way to check the environment, inspect demo data, and create a
minimal synthetic HDF5 input when real PSG data are unavailable.

## Recommended Environment

Use Python 3.10. The upstream repository pins older ML dependencies such as
`torch==2.0.1`, `numpy==1.25.2`, and `scikit_learn==1.3.1`, so Python 3.10 is
the safest target.

Recommended local machine:

- OS: Linux, preferably Ubuntu 22.04/24.04
- Python: 3.10
- Package manager: conda/mamba, or `python3.10 -m venv`
- RAM: 16 GB minimum for light checks, 32 GB recommended for full workflows
- GPU: optional for preprocessing/checks; NVIDIA CUDA GPU recommended for
  full model inference/training

## Installation

### Conda

```bash
git clone https://github.com/sanitka999/SLEEPFM.git
cd SLEEPFM
conda env create -f env.yml
conda activate sleepfm_env
```

### Python venv

```bash
git clone https://github.com/sanitka999/SLEEPFM.git
cd SLEEPFM
python3.10 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### CPU-only option

For machines without CUDA, start with:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements-cpu.txt
```

This is intended for environment checks, preprocessing experiments, synthetic
input generation, and notebook exploration. Full inference still requires the
checkpoint files expected by the demo notebook.

## Quick Checks

```bash
./run_demo.sh check
```

This checks the Python version, key imports, expected demo files, and checkpoint
paths.

## Synthetic HDF5 Input

If real EDF/PSG sample data are unavailable, create a minimal synthetic HDF5
file matching the channel/modalities expected by the dataset loader:

```bash
./run_demo.sh synthetic
```

This writes:

```text
notebooks/demo_data/synthetic_minimal.hdf5
```

The synthetic file contains one channel for each configured modality:

- `C3` for BAS
- `Nasal` for RESP
- `ECG` for EKG
- `Chin` for EMG

The generated signals are artificial sine/noise arrays. They are only for
format and pipeline smoke tests, not for clinical or scientific conclusions.

## Notebook Demo

The upstream demo is:

```bash
cd notebooks

```

The notebook uses synthetic demo data and expects checkpoint directories under:

```text
sleepfm/checkpoints/model_base
sleepfm/checkpoints/model_sleep_staging
sleepfm/checkpoints/model_diagnosis
```

## EDF Preprocessing

For real EDF files:

```bash
cd sleepfm/preprocessing
python preprocessing.py \
  --root_dir /path/to/edf_root \
  --target_dir /path/to/hdf5_output \
  --num_threads 1 \
  --num_files -1 \
  --resample_rate 128
```

The preprocessing step converts EDF PSG recordings into HDF5 files. The
downstream loader expects HDF5 datasets named like recognized PSG channels from
`sleepfm/configs/channel_groups.json`.

## Expected Inputs

- Raw PSG: EDF files.
- Preprocessed model input: HDF5 files.
- Sleep staging labels: CSV with columns such as `Start`, `Stop`, `StageName`,
  `StageNumber`, and optionally `EmbeddingNumber`.
- Disease prediction labels: `is_event.csv`, `time_to_event.csv`, plus
  demographic features such as `demo_age_gender.csv`.

## Expected Outputs

- Preprocessing: `.hdf5` files with PSG channel datasets.
- Embedding generation: HDF5 embedding files.
- Sleep staging: class predictions, F1 scores, confusion matrix.
- Disease prediction: model outputs for condition/phecode labels plus event
  indicator and time-to-event arrays.

## Safety and Limitations

SleepFM outputs should be treated as research or exploratory analytics. They
are not medical diagnoses. Clinical interpretation requires appropriate data
quality checks, validation, regulatory review where applicable, and qualified
medical oversight.

The synthetic files generated by this setup are not physiological recordings.
They exist only to verify file format and plumbing.
